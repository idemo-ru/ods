## 1.1.6.3. Термины и определения {#1-1-6-3}
- **PhaseTransition** (оператор `=>`) — автономная сущность, управляющая трансформацией смысла и переносом состояния между фазами.
- **In-Transition** — состояние между фазами: исходная завершена, целевая не начата.
- **Order parameter** — доминирующее качество новой фазы (по Хакену).

## 1.1.6.4. Область применения {#1-1-6-4}
Обязательна для всех реализаций LifeCycle-6, ChangeFlow-6 и iLang в парадигме ODS. За пределами ODS (императивные, реактивные, событийные модели) фазовые переходы считаются неявными или отсутствующими.

## 1.1.6.5. Каноническое определение {#1-1-6-5}
**PhaseTransition** ≝ процесс утраты устойчивости прежнего режима с диссипацией его ресурсов и формирования устойчивого доминирования нового режима.

- Не мгновенное событие, а процесс с внутренним временем.
- Завершение: прежний режим становится статистическим исключением.
- Неудача: absorbing state — прерывание Flow.

## 1.1.6.6. Функциональные роли {#1-1-6-6}
1. **Изоляция побочных эффектов** — фазы чистые; все side-effects инкапсулированы в переходах.
2. **Самостоятельная точка отказа** — сбой фиксируется как опыт проводимости среды.
3. **Подготовка (CF-6)** — валидация, транспорт, обеспечение ресурсов.
4. **Нормализация (LC-6)** — статистическое доминирование нового качества.


## 1.1.6.7. Типы переходов {#1-1-6-7}
| Тип                  | Описание                                                                 | Синтаксис iLang                          | Длительность   | Примечание / Упрощённое объяснение мгновенных переходов                  |
|----------------------|--------------------------------------------------------------------------|------------------------------------------|----------------|--------------------------------------------------------------------------|
| Условный (логический)| Мгновенный триггер по условию                                             | `=> [/(cond)]`                           | ~0             | Простой if: проверка условия и скачок. Вырожденный случай с нулевым временем. |
| Безусловный          | Естественное завершение фазы                                              | `=>`                                     | ~0             | Фаза закончилась → сразу следующая. Вырожденный случай без проверки.     |
| Процессный (intent-driven) | Автономный intent как двигатель перехода                            | `=> ::intent(...)`                       | переменная     | Полноценный процесс с собственным временем и возможным отказом.          |
| Композитный          | Условие + intent                                                         | `=> [/(cond)] ::intent(...)`             | переменная     | Сначала проверка, затем процесс.                                         |
| Адаптивный (метрика-driven) | Ожидание устойчивости метрики (LC-6)                                | `=> [/(DegradeScore ≤ 0.15 stable Δt)]`   | годы–века      | Нормализация нового качества в жизненном цикле.                          |
| Транспортный         | Асинхронный перенос состояния/данных                                     | `=> ::transport(...)!!`                  | часы–дни       | Передача данных между сервисами/системами.                               |
| Каскадный            | Цепочка переходов с fallback                                             | `-->(logic1) -->(logic2) -->(logic3)`    | переменная     | Fault-tolerant цепочки с резервными вариантами.                          |
| Контрфактический     | Симуляция перехода для обучения без коммита                              | `=> ~simulate(...) _(-1)`                | симуляция      | "Что если" сценарии в evaluate без реального изменения.                  |

## 1.1.6.8. Метрики {#1-1-6-8}
| Метрика                  | Обозначение   | Описание                                                                 | Применение (примеры)                  |
|--------------------------|---------------|--------------------------------------------------------------------------|---------------------------------------|
| Задержка перехода        | τ             | Внутреннее время от завершения исходной фазы до доминирования новой      | Производительность, SLA               |
| Стоимость перехода       | Σ             | Затраты ресурсов (энергия, деньги, время, энтропия)                      | Оптимизация, экономика                |

| Early warning signals    | EWS           | Замедление возврата к равновесию перед утратой устойчивости              | Прогноз критических переходов (LC-6)  |
| Order parameter rate     | dOP/dt        | Скорость формирования доминирующего качества новой фазы                   | Нормализация в climax/degrade         |

| Контрфактическая ценность| CV            | Полезность опыта от неудачных/симулированных переходов                   | Обучение в evaluate                   |

| Физика      | Вода: жидкость → лёд                         | Переохлаждение → кристаллизация (зарождение центров) → рост кристаллов → доминирование твёрдой фазы. |
| Биология    | Метаморфоз бабочки: гусеница → куколка → бабочка | Degrade гусеницы → turn (гистолиз) → transform с реорганизацией тканей → новая идентичность.       |
| Экология    | Озеро: олиготрофное → эвтрофное              | Накопление питательных веществ → tipping point → цветение водорослей → доминирование анаэробного режима. |
| Социум      | Империя: пик → упадок → трансформация/смерть | Утрата устойчивости (коррупция, войны) → точка невозврата → распад или реформация (Рим → Византия). |
| Климат      | Стабильный климат → ледниковый период        | Накопление триггеров → утрата устойчивости → быстрый сдвиг → новая климатическая норма.            |
| Экономика   | Рост → Пузырь → Кризис → Рецессия/Депрессия  | Накопление дисбалансов (долги, спекуляции) → tipping point → лопание пузыря → нормализация новой экономики. |
| Экономика   | Компания: стартап → рост → IPO → зрелость    | Develop → climax (доминирование рынка) → degrade (конкуренция) → turn (pivot или M&A).             |
| Экономика   | Валюта: стабильность → гиперинфляция         | Утрата доверия → ускоренная эмиссия → точка невозврата → коллапс и замена валюты.                  |
| Экономика   | Рынок: бычий → медвежий                      | Эйфория → переоценка активов → паника → распродажа → установление нового равновесия.               |

## 1.1.6.10. Заключение {#1-1-6-10}
PhaseTransition — суверенная мембрана системы: разделяет качество мышления (фаза) и качество взаимодействия (переход). Смерть в переходе — эволюционная цена за уточнение маршрута.

Новизна концепта PhaseTransition в ODS высока: аналогов в софте мало.
Ближайшие: multi-stage programming (MetaML, MetaOCaml, Scala staging) — разделение на фазы для генерации кода, но фокус на compile/runtime stages, не на онтологической утрате устойчивости как в синергетике.
В reactive/actor models (Akka, Erlang) — message-driven переходы состояний, но неявные, без явной модели In-Transition и order parameter.
Риск неадоптации реален на draft-стадии, но решаем: через прототипы, эмпирику в доменах и интеграцию с существующими (e.g., staging в Scala).
Идея уникальна, усиливает чистоту и наблюдаемость.

Scala staging — метапрограммирование для генерации кода в несколько этапов.
Scala 3: Run-time multi-stage programming с quotes '{...} (задержка кода как Expr[T]) и splices ${...} (вставка). Позволяет compile-time macros и runtime code generation.
LMS (Lightweight Modular Staging, Scala 2): Библиотека для runtime code generation через типы Rep[T] — staged вычисления для оптимизированных DSL (e.g., Delite).
Аналог: разделение этапов для специализации кода без overhead.

Scala Quasiquotes (Scala 2): синтаксис вроде q"code $var" для конструкций/деструкций AST в macros (на основе reflection).
Scala 3 Quotes & Splices: замена quasiquotes — '{code} (quote, задержка) и ${expr} (splice, вставка). Более типобезопасны, поддерживают runtime multi-stage programming, без reflection.
Сходство: оба для метапрограммирования и staging (генерация кода по этапам).
Различия: quasiquotes — compile-time macros; quotes/splices — duals, гибче для multi-stage (compile + runtime). Quasiquotes устарели в Scala 3.
