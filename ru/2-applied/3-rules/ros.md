## 2.3.3.1. Основное {#1-1-02-1}
Правило остановки декомпозиции (ROS) определяет минимально допустимый уровень детализации системы, учитывая наличие интентов внутри ChangeFlow.

> *Фаза:* ~~Birth~~ → `Develop` → Climax → Degrade → Turn → End( death | transform )<br/><br class="hidden-wiki"/>
> *Текущий ChangeFlow:* #11<br class="hidden-wiki"/>
> *Фаза:* ~~collect~~ → `analyze` → forecast → decide → implement → evaluate<br/><br class="hidden-wiki"/>

## 1.1.02.3. Термины и определения {#1-1-02-3}
- **ROS (Rule of Stop)** — критерий минимальной детализации при декомпозиции системы.  
- **Intent** — атомарная единица вычислительного намерения, неделимая, не содержащая вложенных ChangeFlow.  
- **ChangeFlow** — композиция интентов, представляющая транзакцию изменений системы; может содержать недетерминированные ветвления (`decide()`).  
- **DaughterLifeCycle(S)** — объект X, классифицируемый как дочерняя система, если внутри есть хотя бы один CF с `decide()`.  
- **NaturalLifeCycle(S)** — объект X без `decide()` внутри всех CF, пассивная детерминированная система.

## 1.1.02.4. Область применения {#1-1-02-4}
Правило применяется при:
- любой декомпозиции всех систем классов 1–6;
- проверке корректности границ LifeCycle и ChangeFlow;
- ограничении глубины регрессионной детализации;
- оценке минимального уровня атомарных интентов.

Не применяется:
- к чистым абстракциям без LifeCycle или ChangeFlow;
- к объектам, чей LifeCycle заранее задан и независим от декомпозиции.

## 1.1.02.5. Формулировка правила {#1-1-02-5}
Декомпозиция останавливается на первом уровне, где выполняется хотя бы одно из условий:
1. Нет новых независимых интентов `decide()` внутри ChangeFlow.  
2. Нет новых физически значимых рисков гибели/трансформации родителя.  
3. Критерии +1/0/–1 совпадают с родителем.  
4. Невозможна локальная реализация `implement()` без нарушения `confinement` родителя.

## 1.1.02.7. Атрибуты / свойства {#1-1-02-7}
- Применяется строго после RLC/CC  
- Запрещает бесконечный регресс  
- Сохраняет причинность и ответственность  
- Учитывает атомарность Intent в ChangeFlow  
- Стоп-критерий основан на недетерминированности (decide) и физически значимых последствиях  

## 1.1.02.8. Связи с другими терминами {#1-1-02-8}
- Родительские: 1.1.01 RLC/CC

## 1.1.02.9. Примеры и иллюстрации {#1-1-02-9}
| Система            | Уровень остановки       | Причина                           |
|--------------------|------------------------|----------------------------------|
| Человек            | Клетка / митохондрия   | 2+3 (новые интенты + совпадение) |
| Корпорация         | Сотрудник              | 1+3                              |
| Адрон              | Валентные кварки       | 1+4 (невозможно implement)        |
| Нейросеть          | Слой / тензор          | 1+2                              |
| Цивилизация        | Государство / мегаполис| 1+3                              |

## 1.1.02.10. Механика исполнения {#1-1-02-10}
1. Определить объект X и его родителя S.  
2. Проверить наличие всех ChangeFlow(X) и интентов внутри.  
3. Проверить физически значимые риски гибели/трансформации родителя.  
4. Сравнить критерии +1/0/–1 с родителем.  
5. Проверить возможность локальной реализации `implement()` без нарушения `confinement`.  
6. Остановить декомпозицию, если выполнено хотя бы одно из условий ROS.  

## 1.1.02.11. Последствия, санкции, отклики системы {#1-1-02-11}
При соблюдении:  
- корректная декомпозиция,  
- минимальный атомарный уровень интентов,  
- сохранение причинности и ответственности.  

При нарушении:  
- система подвержена бесконечному регрессу,  
- невозможна корректная интеграция CF и интентов,  
- требуется переразметка границ LifeCycle.

## 1.1.02.12. Заключение {#1-1-02-12}
ROS совместно с RLC/CC формирует конечное, причинно-корректное дерево систем с атомарными интентами.
