## 1.3.4.1. Основное {#1-3-4-1}

Документ описывает **универсальную рамку метрик для TIL (Transient Integration Layer)**. Цель — дать формальную структуру для оценки реализации ChangeOperators в любых системах, не привязываясь к конкретной предметной области.

> *Версия: doc.1.3.4.v0.1.1 ∙ декабрь 2025*  
> *Текущий LifeCycle:* `Draft` → Candidate → Stable → Canonical  
> *Фаза:* ~~Birth~~ → ~~Develop~~ → Climax → Degrade → Turn → End  
> *Текущий ChangeFlow:* #2  
> *Фаза:* ~~collect~~ → analyze → forecast → decide → implement → evaluate


TIL — это временные реализации ChangeOperators. Метрики этой рамки предназначены для **универсальной оценки эффективности, охвата и качества реализации процессов** в любых системах.

> **Примечание:** Конкретные прикладные метрики (например, биологические, инженерные, ИИ) задаются внутри предметных областей и не входят в рамку универсальных метрик.

## 1.3.4.2. Универсальные показатели {#1-3-4-2}
| Метрика                  | Определение                                                | Единица / Диапазон         |
|--------------------------|-----------------------------------------------------------|----------------------------|
| Execution Duration       | Время выполнения TIL реализации ChangeOperator           | Время (с, мс, циклы)       |
| Resource Consumption     | Затраты ресурсов (энергия, память, вычислительные)       | Абсолютное / нормированное  |
| Coverage (Viewpoint)     | Доля доступных Viewpoint, где TIL реализован             | [0, 1]                      |
| Integration Diversity    | Разнообразие способов реализации ChangeOperator         | Энтропия / индекс Шеннона    |
| Persistence              | Длительность существования TIL                           | Время / жизненный цикл      |
| Fidelity                 | Насколько реализация соответствует идеальному ChangeOperator | [0, 1]                      |
| Availability             | Доступность TIL для использования системой               | [0, 1]                      |
| Context-Intent Fit       | Насколько реализация TIL подходит под конкретный контекст и намерение | [0, 1]                      |

> **Примечание:** Метрики Availability и Context-Intent Fit позволяют оценивать, насколько TIL эффективно применяется для данной задачи. Например, насос может качать нефть, но это неэффективно для контекста воды; Adobe Illustrator можно использовать для верстки, но для многополосного журнала лучше Adobe InDesign.

## 1.3.4.3. Пример расчёта Availability и Context-Intent Fit {#1-3-4-3}
Предположим, система использует TIL для выполнения задачи A. 

- **Availability (Aᵥ)** = количество доступных TIL / общее число требуемых TIL для задачи.  
- **Context-Intent Fit (CIF)** = средняя степень соответствия TIL под контекст и намерение задачи, оценивается по [0,1].

| TIL | Доступен | Контекст / Намерение | Aᵥ | CIF |
|-----|----------|--------------------|----|-----|
| Насос 1 | Да       | Вода               | 1  | 1.0 |
| Насос 2 | Да       | Нефть              | 1  | 0.2 |
| Насос 3 | Нет      | Вода               | 0  | 0.0 |

**Итог:**  
- Availability = (1 + 1 + 0) / 3 ≈ 0.667  
- Context-Intent Fit = (1.0 + 0.2 + 0.0) / 3 ≈ 0.4

Таким образом, TIL в среднем доступен для 2/3 случаев, но соответствие контексту и намерению невысокое.

## 1.3.4.4. Применение рамки {#1-3-4-4}
1. **Сравнение разных систем** — позволяет оценивать эффективность TIL вне зависимости от конкретной области.
2. **Диагностика слабых мест** — выявляет узкие места или недостатки реализации TIL.
3. **Универсальные отчёты** — дают количественные показатели, которые можно агрегировать для мета-анализа.

## 1.3.4.5. Примечания и ограничения {#1-3-4-5}
- Рамка **не определяет предметные метрики**, только универсальные показатели.
- Конкретные системы могут добавлять свои метрики, которые не обязательно будут сопоставимы между доменами.
- Метрики должны оставаться **процессными**, не превращая TIL в объект.

## 1.3.4.6. Связь с ChangeOperators и TIL {#1-3-4-6}
- ChangeOperator: вечный процесс изменения, TIL — его временная реализация.
- Метрики оценивают TIL, а не сам ChangeOperator.
- Универсальные показатели помогают **сравнивать реализации и выявлять закономерности**, не меняя онтологической природы операторов.
