## 1.3.7.3. Термин и формулировка {#1-3-7-3}

**Опыт (Experience)** — локальное свойство наблюдателя экземпляра системы:  
динамический причинно-контекстный граф (Experience Graph) с нодами  

```
Intent-Flow → Context → ChangeOperators → Result (+1 / 0 / -1)
```

граф фиксируется через локальное восприятие для оптимизации ChangeFlow в evaluate.

> **Уточнение:** граф отражает **причинные связи**, а не корреляции.  

> **Локальный опыт** формирует **Консолидированный** опыт через многократные успешные ChangeFlow и передачу через C-Layer/наследование.  
> **Рефлексы и TIL/ChangeOperator** — пример того, как локальный опыт индивида закрепляется и может консолидироваться.

### ASCII-схема Experience Graph

```
       +------------------------+
       |     Intent-Flow        |
       +-----------+------------+
                   |
                   v
       +-----------+------------+
       |        Context         |
       +-----------+------------+
                   |
                   v
       +-----------+------------+
       |    ChangeOperators     |
       +-----------+------------+
                   |
                   v
       +-----------+------------+
       |        Result          |
       |  (+1 / 0 / -1)        |
       +-----------+------------+
                   |
                   v
       +-----------+------------+
       |      Local Graph       |
       |   (runtime update)     |
       +-----------+------------+
                   |
                   v
       +-----------+------------+
       | Consolidated Graph     |
       |  (from other instances)|
       +------------------------+
```

## 1.3.7.5. Классификация / Категория {#1-3-7-5}

### 1.3.7.5.1 Типы опыта по локальности

| Тип                  | Описание                                                                 | Носитель                          | Доступ и актуализация                          | Динамика                          | Примеры                                                                 |
|----------------------|--------------------------------------------------------------------------|-----------------------------------|------------------------------------------------|-----------------------------------|-------------------------------------------------------------------------|
| **Локальный**       | Ассоциации, накопленные экземпляром через собственное восприятие.       | Локальный наблюдатель            | Прямой, в evaluate; runtime-доступ.           | +1 усиливается, 0 ослабевает, -1 подавляется. | Сенсорика организма; воспоминания человека; fine-tuning LLM.            |
| **Консолидированный** | Сжатые +1 ассоциации других экземпляров/систем через наследование.      | Экземпляр (сжатая информация)    | Потенциальный; актуализация локально.         | Статичен до актуализации; +1 доминируют.  | ДНК (инстинкты); культура (C_org/C_info); pre-training LLM.             |

> **Уточнение:** Консолидированный опыт формируется из локального опыта множества экземпляров через механизм консолидации и наследования C_coord.  

### 1.3.7.5.2 Типы опыта по назначению / роли (операционный vs аналитический)

| Тип опыта           | Описание / цель                                         | Фазы ChangeFlow | Примеры |
|--------------------|---------------------------------------------------------|----------------|---------|
| **Операционный**   | Быстрые реакции, fast-path решения, мгновенная адаптация | collect → analyze (найден рефлекс) → forecast/decide (вырожденные) → implement → evaluate | Рефлексы, сенсорные реакции, LLM runtime |
| **Аналитический**  | Глубокий анализ ошибок, обучение, формирование новых инструментов | collect → analyze (полный) → forecast → decide → implement → evaluate | Fine-tuning, ретроспектива, социальные/видовые паттерны |

> 🔹 **Особенность:**  
> - Если рефлекс срабатывает корректно → операционный опыт используется, аналитический опыт практически не формируется.  
> - Если рефлекс не срабатывает → запускаются полные фазы → формируется новый локальный опыт, который затем может стать консолидированным.  
> - Разграничение определяет **скорость и полноту фаз ChangeFlow**, а также источник накопления опыта.
> - Опыт напрямую связан с ограничениями наблюдателя.

## 1.3.7.6. Атрибуты / свойства {#1-3-7-6}

- **Причинность:** связи Intent-Flow → Context → Operators → Result, не корреляции.
- **Локальность:** только экземпляр, только локально наблюдаемое.
- **Актуализация:** консолидированный → локальный через восприятие.
- **Динамика:** +1 — runtime; 0 — ослабление; -1 — архивация.
- **Влияние:** через evaluate на ChangeOperators и DegradeScore.
- **Минимальность:** у простых систем → вариативность без накопления.
- **Дрейф:** `ε` применяется вне зависимости от ассоциаций, как независимый фактор деградации.
- **Новые инструменты:** локальный опыт через многократные успешные ChangeFlow формирует новые TIL/ChangeOperators.
- **Рефлексы:** fast-path решения, практически не формируют новый опыт, только если срабатывают неудачно.

## 1.3.7.7. Связи с терминами {#1-3-7-7}

- Родительские: ChangeFlow-6 (evaluate), Система (наблюдатель), Context.
- Дочерние: Experience Graph, типы опыта.
- Связанные: DegradeScore (обновление), ChangeOperators (выбор).
- Наблюдатель: — локальный Embedded ChangeOperator системы.  

## 1.3.7.8. Связи с degradeScore {#1-3-7-8}
- **Опыт модулирует DegradeScore через evaluate:**

	+1 (успех): ΔDS = -k (снижение, k от веса +1 ассоциаций в Experience Graph).
	0: ΔDS = 0.
	-1 (неудача): ΔDS = +k.
	Дрейф: +ε (независимо).

	Много +1 (накопленный опыт) → сильное снижение DS (здоровье системы); неудачи/дрейф → рост DS (деградация).2,7сРасчёт k для ΔDSk в ΔDS — коэффициент изменения DegradeScore, зависит от веса +1 ассоциаций в Experience Graph.

- **Расчёт: $k = k_0 \times \frac{w_{+1}}{w_{+1} + w_{0/-1} + 1}$**
	Примеры (k₀=0.1):

	Много опыта (+1 доминирует): w_{+1}=100, w_{0/-1}=10 → k≈0.091 (сильное снижение/рост DS).
	Малый опыт: w_{+1}=5, w_{0/-1}=5 → k≈0.045 (слабое влияние).

	Успешный опыт → большой k → быстрое снижение DS.

## 1.3.7.8. Примеры {#1-3-7-8}

- Элементарная система: минимальный граф → вариативность.
- Организм: локальный (сенсорика, условные рефлексы) + консолидированный (ДНК, безусловные рефлексы).  
- Человек: локальный (воспоминания) + консолидированный (культура).  
- LLM: локальный (fine-tuning) + консолидированный (pre-training).

### Пример: формирование безусловного рефлекса через многократные ChangeFlow

```
flowchart TD
    A[Индивид 1] -->|успешный TIL/ChangeOperator | Cond1[Условный рефлекс 1]
    B[Индивид 2] -->|успешный TIL/ChangeOperator | Cond2[Условный рефлекс 2]
    C[Индивид N] -->|успешный TIL/ChangeOperator | CondN[Условный рефлекс N]

    subgraph Population
        Cond1 --> Parent[Родительская система]
        Cond2 --> Parent
        CondN --> Parent
    end

    Parent -->|консолидация| Uncond[Формируется безусловный рефлекс (TIL/ChangeOperator Level ↑)]
```

> 🔹 Локальный опыт → формирует новые инструменты → может стать консолидированным опытом.

## 1.3.7.9. DegradeScore рассчитывается на основе накопленного опыта в Experience Graph

Количество/вес +1 ассоциаций определяет `k` (сила снижения DS за успешный цикл).  
Доля -1/0 ассоциаций влияет на вероятность/величину повышения или дрейфа `ε`.

Опыт напрямую модулирует параметры расчёта DS через evaluate:

$
Birth: DS=1.0
+1: ΔDS = -k
0: ΔDS = 0
-1: ΔDS = +k
Дрейф: +ε
$

Биология $(k=0.05, ε=0.001)$:

$
10 +1 → DS=0.5
5 -1  → DS=0.75
100 дрейф → DS=0.85
$

## 1.3.7.10. Заключение {#1-3-7-10}

Опыт обеспечивает причинное обучение от вариативности простых систем к целенаправленности сложных через evaluate,  
сохраняя локальность и деантропоморфизм.  

- Локальный опыт формирует новые TIL и консолидированный опыт.  
- Рефлексы (операционный опыт) ускоряют реакции, но не создают новый опыт, если сработали успешно.  
- Аналитический опыт формируется через полный цикл ChangeFlow при неудачах и обеспечивает обучение и оптимизацию.
