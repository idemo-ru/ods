Документ описыывает Универсальную онтологию устойчивого целенаправленного изменения системы.  

## 1.1.02.3. Термин и формулировка {#1-1-02-3}
**ChangeFlow-6** ≝ строго упорядоченная последовательность шести фаз:  
collect → analyze → forecast → decide → implement → evaluate  
где каждая фаза выражается композицией Primitive Intent’ов, а весь цикл в чистом виде составляет один Composite Intent реализующий контракт фаз Changeflow.

CF-6 как универсальная структура:
Шестифазный ChangeFlow collect → analyze → forecast → decide → implement → evaluate не является антропоморфной метафорой. Каждая фаза отражает функциональную и наблюдаемую роль в процессе изменения любой системы класса ≥1. Например, для одиночного электрона в вакууме каждая фаза имеет изоморфный физический аналог: измерение, фильтрация, прогноз суперпозиции, коллапс волновой функции, физический переход, фиксация состояния. Таким образом, CF-6 демонстрирует универсальную изоморфность, сохраняющую идентичность логических и функциональных ролей независимо от предметной области и терминологии.


## Постулат фазовой полноты (Теорема ChangeFlow-6)
Любая система, способная к устойчивому целенаправленному изменению в нетривиальной среде, выполняет шесть логически необходимых фаз:
`collect → analyze → forecast → decide → implement → evaluate`

- Функции этих фаз неустранимы и функционально несливаемы по смыслу, хотя на практике отдельные процессы могут делегироваться, интегрироваться или комбинироваться, не теряя своей онтологической роли.
- Любое добавление новых фаз не создаёт принципиально новые функции и редуцируется к этим шести по смыслу и ответственности.

> Итеративность системы реализуется исключительно как последовательность полных циклов ChangeFlow.
> Ни одна фаза ChangeFlow не допускает локального зацикливания или отката; любые коррекции возможны только в последующих циклах, начиная с нового состояния S₀.

> Фазы ChangeFlow-6 не допускают параллельного выполнения по причине строгой каузальной зависимости: каждая фаза требует завершённого семантического результата предыдущей.
> Параллелизм возможен исключительно внутри реализации фазы и никогда между фазами одного ChangeFlow.
> Параллелизм возможен исключительно c учётом relation ChangeFlow.

> Так же запрещены откаты; коррекции — только через новые корректирующие ChangeFlow на обновлённом S₀.

> Валидация Intent на входе (осмысленность как precondition collect).

## Каноническое описание шести фаз

| # | Фаза        | Функциональная ответственность (SRP)                                                                                             | Ключевая онтологическая роль                                           |
|---|-------------|-----------------------------------------------------------------------------------------------------------------------------------|------------------------------------------------------------------------|
| 1 | **collect**   | Сбор текущего состояния системы и её контекста (S₀)                                                                              | Фиксация «здесь и сейчас»                                              |
| 2 | **analyze**   | Фильтрация сигнал/шум, сопоставление триггера с доступными инструментами и ресурсами                                           | Устранение энтропии входа                                              |
| 3 | **forecast**  | Построение суперпозиции допустимых будущих траекторий (включая квантовые амплитуды и ветвление кода)                             | Создание карты возможного                                              |
| 4 | **decide**    | Единственная точка бифуркации и необратимого коллапса суперпозиции в одну детерминированную траекторию                           | Коллапс волновой функции любой природы                                 |
| 5 | **implement** | Строго детерминированная физическая реализация выбранной траектории с реальной затратой энергии/времени                           | Единственный необратимый физический коммит (информация → работа)      |
| 6 | **evaluate**  | Фиксация результата, оценка (±1 / 0) и обновление графа опыта системы. Единственная фаза, влияющая на DegradeScore LifeCycle     | Обучение и единственная связь ChangeFlow ↔ LifeCycle                   |

## Фундаментальные принципы ChangeFlow-6

1. **Атомарность** — шесть фаз образуют неделимый атомарный цикл изменения состояния.
2. **Распределённость** — collect, analyze, forecast, decide, evaluate могут быть делегированы. **implement** — всегда строго локален.
3. **Единственная точка бифуркации** — decide  
4. **Единственная точка необратимого физического коммита** — implement  
5. **Единственная точка изменения DegradeScore** — evaluate  

## Шесть доказанных от противного гипотез

| Гипотеза | Отсутствие фазы приводит к…                                   | Фатальное следствие                     |
|----------|---------------------------------------------------------------|-----------------------------------------|
| H1 collect   | Действие без знания S₀                                        | Хаос и потеря причинности               |
| H2 analyze   | Полная энтропия входа                                         | Экспоненциальная смерть (закон Эшби)   |
| H3 forecast  | Нет отсева невозможного                                       | Мгновенная катастрофа                   |
| H4 decide    | Вечная суперпозиция / Буриданов осёл                          | Исчерпание ресурсов                     |
| H5 implement | Информация не превращается в работу                           | Функциональная смерть                   |
| H6 evaluate  | Нет обучения и рефлексов                                      | Эволюционная смерть                     |

## Фазовый переход и его топология {#tmp-1-1-6-10-ext}

Принцип Активного Шлюза: Фазовый переход => не является мгновенным переключением флага. Это автономный процесс трансформации смысла из одного качества в другое. {.is-info}

Фазовый переход — это потеря устойчивости предыдущего качества и формирование нового, происходящее во внутреннем времени и сопровождающееся диссипацией ресурса старой фазы.

> v.2 Фазовый переход — процесс утраты устойчивости прежнего режима (фазы) с диссипацией его ресурсов и формирования устойчивого доминирования нового режима (order parameter по Хакену).
> 
> Мгновенные переходы — предельный случай (mean-field approximation).
> Процессные переходы включают внутреннее время, In-Transition состояние и early warning signals (замедление возврата к равновесию).
> Неудачный переход ведёт к absorbing state: прерыванию ChangeFlow.
> Завершение перехода: прежний режим становится статистическим исключением; "возвраты" — хвост распределения.

**Типы переходов:**
- Условный переход — логический триггер
	Фаза меняется мгновенно, как только A === true.
	Процесс перехода не моделируется.
- Процессный (интентный) переход — через f(*)
	Новая фаза наступает только после завершения функции/интента перехода.
	У перехода есть собственное время, возможен отказ, состояние In-Transition.
- Безусловный переход — чистая последовательность
	Фаза завершилась → сразу стартует следующая.
	Частный случай, где условие всегда истинно.

Структура оператора =>
Оператор может принимать три формы реализации «двигателя» (Engine):

Мгновенный (Trigger): => [/(condition)]

Используется для логических скачков, где задержка пренебрежимо мала.

Процессуальный (Intent-driven): => ::intent_name(...)

Переход считается активным, пока вызванный интент не достигнет фазы End.

Весь LC-6 вызванного интента становится «внутренним временем» перехода.

Композитный: => [/(condition)] ::intent_name(...)

Интент-двигатель запускается только при выполнении логического условия.

Статус потока в моменте перехода
Во время выполнения => ::intent:

Исходная фаза считается завершенной (ресурс диссипирован).

Целевая фаза считается не начатой (ресурс не рожден).

Система находится в состоянии Перехода (In-Transition).

Если интент перехода умирает (-), основной Flow прерывается (!) в точке между фазами. Это исключает ситуацию, когда данные «зависли» в неопределенном состоянии внутри фазы. {.is-warning}

> Смена фазы — это не событие, а процесс утраты устойчивости старого режима и формирования устойчивости нового.
>
> Моментальные переходы — это предельный, упрощённый случай.
> Достижение порогового значения метрики не является фазовым переходом.
> Фазовый переход считается завершённым только при формировании устойчивого режима, в котором прежнее состояние становится статистическим исключением.
{.is-info}

И «возвраты» — это не откат, а хвост распределения перехода.

> Фаза определяется не моментом достижения признака, а устойчивым статистическим доминированием режима; фазовый переход — это процесс, в котором прежний режим становится исключением а его завершение определяется тотальным доминированием нового режима.
{.is-success}


## 1.1.02.4. Область применения {#1-1-02-4}
Все динамические процессы в системах классов 3–6, где реально проявляется полный ChangeFlow-6.

Системы классов 0-2:
1.	Фазовая полнота ChangeFlow-6 остаётся верным определением для систем с устойчивым целенаправленным изменением (классы ≥2), где реально проявляются все шесть фаз.
2.	Детерминированные / объектные системы (классы 0–1) явно выделены с упрощённым ChangeFlow: только implement() локально.
	•	Остальные фазы либо отсутствуют, либо делегируются субъекту/родительской системе.
	•	Это устраняет сомнения о необходимости выполнения всех шести фаз для простых или детерминированных систем.
3.	Примеры и пояснения (рулетка, камень, звезда) показывают, как вероятность и случайность связаны не с implement(), а с инструментами субъекта (ChangeOperators) на фазах analyze/forecast/decide.
4.	Выводы о вероятности встроены корректно: вероятность — это характеристика когнитивного слоя субъекта, а не физической системы реализации.

## Режим выполнения ChangeFlow

Любой ChangeFlow-6 может выполняться в одном из двух режимов:

1. **Operational Mode**  
   - Используется fast-path: быстрые реакции, вырожденные analyze/forecast/decide, implement локален, evaluate минимален.  
   - DS служит триггером для оценки риска; операции выполняются сразу.  

2. **Analytical Mode**  
   - Полный цикл ChangeFlow-6: все шесть фаз активны, evaluate раскрывает Experience Graph и доменные метрики rrᵢ.  
   - Используется для обучения, оптимизации, построения новых ChangeOperators и TIL.  

**Применимость по классам систем:**
- Class 0–1: только Operational Mode (только implement локально; остальные фазы делегированы).  
- Class ≥ 2: допустимы оба режима; переключение в Analytical Mode происходит при DS → 0 (или на основе триггера риска).

## Корректировка ChangeFlow для детерминированных систем (классы 0–1)
> сверить с предыдущим пунктом
Постулат:

Любая детерминированная или объектная система имеет упрощённый ChangeFlow, ограниченный строго локальной фазой implement(). Все остальные фазы (collect, analyze, forecast, decide, evaluate) выполняются либо родительской системой, либо субъектом, инициирующим ChangeFlow.

Примеры:
Система
ChangeFlow локально
Примечание
Рулетка
implement()
Физическая реализация сценария; вероятность — на уровне крупье
Камень
implement()
Состояние сохраняется; нет субъектного выбора
Звезда
implement()
Эволюция строго детерминирована
Следствия:
	1.	Вероятность не встроена в объектную систему; она — инструмент анализа субъекта.
	2.	Любая “случайность” — отражение ограниченности ChangeOperators.
	3.	ChangeFlow сохраняет каноничность, но для детерминированных объектов сокращается до implement().

## 1.1.02.10. Заключение {#1-1-02-10}
ChangeFlow-6 — не просто поток изменений; это онтологический регулятор системной стабильности и эмерджентной когерентности, обеспечивающий логическую и энергетическую адаптивную балансировку системы между состояниями стабильности и нестабильности.
