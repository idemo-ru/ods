# 1.1.4. ChangeOperators: Процессная онтология

## 1.1.4.1. Основное {#1-1-4-1}
Документ описывает **ChangeOperators как первичные механизмы изменения**, реализуемые в контексте C для преобразования X → Y.
Операторы **не являются объектами или фиксированными наборами**, они **существуют только через акты изменения**. Все формальные модели (математика, физика, языки программирования и др.) служат средствами описания, анализа и предсказания этих актов.

## 1.1.4.3. Термины и определения {#1-1-4-3}
- **ChangeOperator** — механизм изменения X → Y в контексте C; существует только через реализацию процесса изменения, не как объект или фиксированный набор.  
- **L/P/S/E-operators** — Local / Parent / Sibling / External (по источнику доступа и области действия)

## 1.1.4.4. Область применения {#1-1-4-4}
Применимо ко всем системам с **реализуемым ChangeFlow** (биологические, когнитивные, социальные, технические, ИИ).  
Не применимо к статичным объектам без процессов изменения и репликации.

## 1.1.4.5. Типология ChangeOperators {#1-1-4-5}
| Тип        | Описание                                      | Примеры                              |
|------------|-----------------------------------------------|--------------------------------------|
| Natural    | Реализуются независимо от наблюдателя        | Логика, математика, физика           |
| Constructed| Реализуются через искусственные процессы      | Алгоритмы, языки, нейросети          |
| Emergent   | Возникают в ходе взаимодействия систем       | Деньги, мемы, социальные нормы       |
| Embedded   | Встроены в архитектуру систем                | Рефлексы, инстинкты, предобучка      |
| Meta       | Реализуются над другими операторами          | Viewpoint, рефлексия                 |
| Hybrid     | Комбинируют разные механизмы изменения       | Человеческий мозг, LLM               |
| Transient  | Реализуются лишь в рамках одного ChangeFlow | Одноразовый промпт                   |
| Forbidden  | Реализация заблокирована системой           | Деструктивные паттерны               |

> **Примечание:** «Тип» описывает способ реализации, а не фиксированную сущность.

## 1.1.4.6. Классификация по доступу {#1-1-4-6}
| Тип      | Обозначение | Источник              | Уровень инновационности |
|----------|-------------|-----------------------|--------------------------|
| Local    | L           | Текущий цикл          | Низкая                   |
| Parent   | P           | Наследование          | Базовая                  |
| Sibling  | S           | Смежные системы       | Средняя                  |
| External | E           | Удалённые системы     | Высокая / прорыв         |

> **Примечание:** Классификация отражает динамику доступа к реализуемым операторам.

## 1.1.4.7. Минимальный обязательный набор по фазам ChangeFlow {#1-1-4-7}
| Фаза         | Обязательные ChangeOperators                     |
|--------------|--------------------------------------------------|
| collect      | Сенсорные / наблюдательные                       |
| analyze      | Логические, модельные, семантические             |
| forecast     | Математические, вероятностные                    |
| decide       | Разрешение неопределённости                      |
| implement    | Физические / исполнительные (локальные)          |
| evaluate     | Метрики, сравнения                               |

> **Примечание:** Обязательные наборы описывают **процессы, реализуемые в фазе**, а не фиксированные объекты.

## 1.1.4.9. Заключение {#1-1-4-9}
**ChangeOperators — первичные механизмы изменения.**  
Все системы, прогресс и креативность — это разные способы реализации этих механизмов через Viewpoint и TIL.  
Математика, физика, языки программирования и другие формальные модели **описуют и анализируют эти механизмы**, но не создают их и не являются сущностями.
