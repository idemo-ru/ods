## 1.1.5.3. Термины и определения {#1-1-5-3}
- **Intent:** атомарная единица вычислительного намерения, определяющая что должно произойти в системе, без указания способа исполнения.

- **Свойства Intent:**
	- Осмысленность — Intent всегда описывает цель.
	- Чистота — Intent не содержит операторов реализации.
	- Детерминируемость — один Intent = одно ожидаемое состояние результата.
	- Контекстуальность — смысл Intent зависит от подключённого контекста.
	- Репродуцируемость — Intent может быть повторно исполнен с любым набором операторов.

- **LC-6:** LifeCycle-6 *(см. связанные документы)*;
- **CF-6:** ChengeFlow-6 *(см. связанные документы)*;
- **CO:** ChangeOperators *(см. связанные документы)*;

## 1.1.5.4. Область применения {#1-2-5-4}
Описание и моделирование LC-6 и CF-6 в любых предметных областях вплоть до смысловых атомов.

## 1.1.5.5. Принцип ~ Разделения Намерения и Исполнения {#1-2-5-5}
> Intent определяет «что», а не «как»
{.is-info}

Реализация всегда вторична и динамическая. Код — производная, временная, усиливаемая обучением и не сохраняемая.

> ## Почему Intent — первооснова
> 1.	Онтологическая чистота
> o	Intent не содержит реализации → не привязан к языкам, архитектурам, инфраструктуре.
> o	Он — минимальная недекомпозируемая единица смысла в вычислении.
> 2.	Намерение порождает смысл, а не наоборот
> o	Смысл — это свойство Intent.
> o	Intent — это оператор цели; смысл — результат интерпретации.
> 3.	Данные и код становятся частью контекста, а не основания
> o	Данные используются только как материал для интерпретации Intent.
> o	Код — лишь временная реализация («эпифемерный код») порождаемая Intent-операторами.
> 4.	Реализация становится полностью производной и обучаемой
> o	Intent остаётся неизменным → DSL уровня смыслов стабилен.
> o	Операторы реализации могут эволюционировать бесконечно.
> 5.	Вычисление становится обратимо-детерминированным
> o	Хранится Intent и опыт исполнения → система способна воспроизводить и улучшать собственные реализации.
> 
> Итого: ```Intent``` — не программа, не запрос, не данные, не код.
Это ```квант вычислительного смысла```.

## 1.1.5.6. Корневые топологические Intent - примитивы {#1-1-5-6}
Примитивы связанные с фазами LC-6, CF-6, осушествляющие фазовые переходы.
| Символ | Имя          | Смысл                                   | Связь с ChangeFlow / LifeCycle |
|--------|--------------|-----------------------------------------|---------------------------------|
| `+`    | birth        | Породить новую сущность                 | Birth                          |
| `−`    | death        | Завершить существование                 | End → death                    |
| `=`    | transform    | Сохранить идентичность при смене формы  | Turn → transform               |
| `+=`   | develop      | Увеличить сложность / эффективность     | Develop → Climax               |
| `-=`   | degrade      | Уменьшить сложность / эффективность     | Degrade                        |
| `?`    | collect      | Собрать контекст / данные               | collectData                    |
| `??`   | analyze      | Осмыслить, отфильтроватьб исследовать   | analyze                        |
| `~`    | forecast     | Спрогнозировать варианты исходов        | forecast                       |
| `^`    | decide       | Разрешить неопределённость, выбрать вариант (коллапс неопределённости). Ветвление     | decide                         |
| `>`    | implement    | Реализовать | implement                      |
| `_`    | evaluate     | Зафиксировать результат (записать новое состояние)     | evaluate                       |

## 1.1.5.7. Корневые процессные Intent - примитивы {#1-1-5-7}
| Символ | Имя          | Смысл                                   | Связь с процессом |
|--------|--------------|-----------------------------------------|---------------------------------|
| `/`    | split        | Разделить поток / сущность              | ветвление                      |
| `*`    | merge        | Объединить потоки / сущности            | слияние                        |
| `!`    | reflect      | Рефлексия                               | обучение                       |
| `<>`   | wait         | Ожидать условия                         | синхронизация                  |
| `**`   | repeat       | Повторить с условием/счётчиком          | циклы                          |

## 1.1.5.8. Структурные Intent {#1-1-5-8}
| Символ | Имя          | Смысл                                   |  |
|--------|--------------|-----------------------------------------|---------------------------------|
| `$`    | flow        | Экземпляр топологических flow LC-6, CF-6.  Наследует контракт фаз LC-6, CF-6 [см. п. 1.1.5.__n__](#1-1-5-__n__)           |                       |
| `$name`    | named_flow        | Именованый экземпляр топологических flow LC-6, CF-6.             |                       |
| `@`    | context        | Контекст            |                         |
| `=>`    | phase_transition      | Оператор фазового перехода LC-6, CF-6.                           |                        |
| `::`    | external_intent  | Внешний функциональный интент (либо параллельный, либо первый в цепочке (step 1)                               |                        |
| `result::`    | result_variable     | Внешний функциональный интент с присвоением результата переменной                               |                        |
| `->`   |  external_intent_chain     | Внешний функциональный интент в цепочке (step > 1)                          |                   |
| `::()`   |  external_intent_closure       | Внешний функциональный интент как замыкание                          |                   |
| `->()`   |  external_intent_chain_closure       |  Внешний функциональный интент в цепочке как замыкание                        |                   |

## 1.1.5.9. Контекст и пространства имён. {#1-1-5-9}
Предполгагается создание общего Доменного Классификатора, однако можно использовать локальные Классификаторы. Главное чтобы они были определены.
- 1.1.5.9.1. Общая структура пути. {#1-1-5-9-1}
```yaml
@domain.subdomains_path.entity:inner_path;		# Полный путь в качестве алиаса используется последний сегмент пути.
@domain.subdomains_path.entity:inner_path as alias;		# Полный путь в качестве алиаса используется последний сегмент пути.
@*socium.subdomains_path.entity:inner_path;	# Короткий путь. 
																							# Недостающий путь до * будет взят из классифткатора доменов по первому сегменту после * (в данном случае socium). 
                                              # Если не найден учитывается оператор !@
                                              # Либо следует прописать полный путь
@alias:path                                   # короткая запись
!@path                                        # строгое подключение 
																							# (ошибка, если недоступно)
@path                                         # опциональное (продолжить без него)

# Пример (псевдокод)
@biology.human:brain.neuron;
@business.logistic.tech.crm.company as buyer;
@business.logistic.marketing.crm.user as manager;
```
- 1.1.5.9.2. Импорт контекста. {#1-1-5-9-2}
```yaml
import @domain.subdomains_path.entity as alias      	# по полному пути с присвоением алиаса
```
- 1.1.5.9.3. Локальные контексты. Используюься локально в пределах $. {#1-1-5-9-3}
```yaml
  @output_mess:
  	success: 'Успех'
    error: 'Ошибка'
  # Единично
  @output_success_mess = 'Успех';
  @output_error_mess = 'Ошибка';
```
- 1.1.5.9.4. Дополнительные конструкции. {#1-1-5-9-3}
```yaml
@path:timeout=5s                              				# с таймаутом
/cond > @alias_1:path, @alias_1:path									# подклбчение по условию в теле flow
/cond > (/cond > @alias_1:path, @alias_1:path), @alias_3:path # подклбчение по цепочке условий в теле flow
```

## 1.1.5.10. Обязательные топологические контракты Flow {#1-1-5-10}
> Каждый Flow обязан содержать ровно 6 фаз в строгом порядке
{.is-info}
### Контракты

- LC-6:
``` yaml
#import...

$lc_name
	@context...
	=> *** #birth
	=> *** #develop
	=> *** #climax
	=> *** #degrade
	=> *** #turn
	=> *** #end(death: dissipate | transform: new $lc_name)
```
- CF-6:
```yaml
$cf_name
	@context...
	=> *** #collect
	=> *** #analyze
	=> *** #forecast
	=> *** #decide
	=> *** #implement
	=> *** #evaluate 

```
### Оператор фазового перехода
Может быть 
- условным:
```php
=> [cond] ?(next collect phase)
```
- безусловным:
```php
=> [] ^(next decide phase)
``` 
Короткий синтаксис безусловного оператора фазового перехода:
```php
=> ^(next decide phase)
```
  * Безусловный подразумевает естественное завершение предыдущей фазы (например завершение вычислений алгоритма).
## 1.1.5.11. Примеры структурных интентов. {#1-1-5-11}
```yaml
# Внешний именованный интент

# Обявление runtime
::get_user
	? user.id = 123;
::set_user
	? user = io.user;
	+ user;
  
# Импорт
 import ::get_user from path;
 import ::set_user from @crm.context.set_user;
 
# Вызов в теле $
=> ::get_user

#Вызов цепочки в фазе $ с присвоением результата переменной
$
	@crm.users;
  @local.mess:
  	success: 'Успех'
    error: 'Ошибка';
  @kafka;
  => ?users.id = 123; 	//collect
  =>	any logic					//analyze	
  =>	any logic					//forecast	
  => any logic					//decide	
	=> > result::get_user		//implement
					->set_user;
			_state.result as result #Запись в состояние системы
  => evaluate
  	/result == +1 > kafka.topic = local.mess.success, kafka.topic = local.mess.error;
  		
```
